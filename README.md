# nice-bust4-ng

Новое поколение компонента ESPHome для приводов Nice по шине BusT4.
Репозиторий: https://github.com/pruwait/nice-bust4-ng, компонент в YAML называется `nice_t4`.

## Состояние

Работает: кодек кадров, приём, очередь запросов, управление воротами (открыть, закрыть, стоп, SBS, частичное
открывание и другие команды DEP), состояние по событиям привода и по опросу регистра 01.
Не готово (этап P2 и далее): опрос привода при включении, меню поддерживаемых команд по модели, параметры,
приёмники и пульты. План: `docs/plan.md`.

## Подключение

```yaml
external_components:
  - source: github://pruwait/nice-bust4-ng@main
    components: [nice_t4]
```

Примеры: `examples/esp32.yaml`, `examples/esp8266.yaml`. Пины задаются в стандартном компоненте `uart`
(19200 бод, 8N1; другие значения отвергаются при проверке конфигурации).

## Опции хаба `nice_t4`

| Опция | По умолчанию | Назначение |
|---|---|---|
| `address` | `0x0066` | адрес модуля на шине: старший байт ADR, младший EPT (EPT не `00` и не `FF`) |
| `target` | `0x00FF` | адрес привода; `0x00FF` это все устройства сети 0 |
| `identity` | `oview` | DEVICE в кадрах команд: `oview` или `it4wifi` |
| `break_mode` | `byte` | `byte`: простой байт `00` на 19200 (проверено на RB500HS); `baud`: `00` на 9200 бод |
| `allow_commands` | `true` | команды управления |
| `allow_write` | `false` | запись параметров привода (SET) |
| `status_poll_interval` | `15s` | опрос состояния, `0s` отключает |

Платформы: `cover` (открыть, закрыть, стоп, переключить), `button` (любая команда DEP по имени или коду),
`text_sensor` (`status`, `last_event`). Остальные типы text_sensor из плана вернут ошибку конфигурации до этапа P2.

Команды отправляются один раз: у DEP нет ответа DMP, подтверждение приходит событием. Состояние cover берётся
только от привода, оно не предполагается после нажатия.

## Проверка

```
make test                     # ядро: 32 теста с -Wall -Wextra -Werror и sanitizers
make gen                      # пересоздать генерируемые файлы из data/ и tests/vectors.json
./tools/check_esphome.sh      # yaml для esp32 и esp8266, отвергаемые конфигурации, синтаксис C++ с заголовками ESPHome
```

Последний скрипт требует `pip install esphome`. CI (`.github/workflows/ci.yml`) запускает всё это при каждом push.

## Состав

| Файл | Назначение |
|---|---|
| `components/nice_t4/t4_types.h` | константы и перечисления |
| `t4_frame.*` | кадр, XOR-суммы, сборка и разбор DEP и DMP, безопасный hex-дамп |
| `t4_rx.*` | приёмный автомат с повторной синхронизацией |
| `t4_engine.*` | очередь запросов, пауза на шине, повторы, сопоставление ответов; интерфейс `Transport` |
| `t4_chunk.*` | постраничное чтение (RUN `18` и `19`) |
| `t4_state.*` | состояние ворот по событиям и по регистру 01 |
| `uart_transport.h` | адаптер `Transport` поверх `uart` |
| `nice_t4_hub.*`, `__init__.py` | хаб компонента |
| `cover.py`, `button.py`, `text_sensor.py` и `nice_t4_*.h/.cpp` | платформы |
| `t4_registers.h`, `t4_cmds.h`, `command_codes.py` | таблицы регистров и команд (генерируются) |
| `tests/vectors.json` | 159 проверенных кадров из спецификации протокола |

Лицензия не выбрана. Код написан по спецификации протокола, без копирования чужого кода.
